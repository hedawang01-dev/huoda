# 活搭 HUODA v0.5.2｜团队改进方案

日期：2026-09-11。基于工作目录 huoda_v050 的 v0.5.1 及其已有未提交修改。

## 目标与取舍

用户授权活搭团队自行检查、提出提升并实施，只验收最终成果。本轮由前端开发、后端架构、测试自动化角色并行工作，Codex 负责跨层整合、实际页面检查与交付。

比较三个方向：只调整视觉不能解决数据错乱；增加支付、地图、短信等需要新的服务与业务前提；优先修复现有流程的可靠性收益更直接。因此保留墨黑、暖白、青柠绿和同一套手机/电脑代码，修复已复现的使用障碍，不重写平台。

## 实施范围

1. 页面可恢复：任务深链接、浏览器前进后退、任务不存在时可重试。
2. 输入可保留：按账号和会话隔离的标签页草稿，发布/发送防重复，成功写入与后续刷新失败分开处理。
3. 身份隔离：用户身份世代标识；账号 A→B→A 的旧响应同样失效；业务列表原子提交，排队写入不跨账号执行。
4. 异步页面正确性：收藏、消息搜索、详情和后台队列拒绝过期响应；分页失败保留已加载内容。
5. 消息历史：补充受参与者权限保护的游标接口，修复仅最近200条导致旧约定不可查看的问题；客户端每次只取200条，历史由用户主动加载；自动更新保留已加载记录，突发大批新消息时重置连续窗口避免漏页。
6. 异常恢复：断网/更新失败提示与重试；网络失败不冒充任务关闭；不在无关页面下载聊天正文。
7. 本地预览边界：仅提供页面所需静态资源，避免开发脚本、SQL、依赖目录被HTTP读取；审核后台不完整云配置不得降级本地模拟。

## 保存与验证

修改前副本：工作区 备份/v0.5.1_团队改进前_20260911_114707。历史交付及用户已有改动保留。

基线：35个JS语法检查、23项自动化测试通过。新增针对真实缺陷的浏览器、服务边界与数据库测试；最终以全套通过结果和六种尺寸渲染检查为准，不只检查脚本语法。新增迁移只追加，不覆盖已发布迁移。

真实 Supabase 配置未提供，本轮可交付完整接入代码、迁移和测试，但不能把本地替身合同测试当成已上线或已验证真实手机电脑互通。
