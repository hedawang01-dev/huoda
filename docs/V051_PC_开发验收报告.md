## 3. PC 首页结构

最大 1400px 居中。完整桌面为三栏：204px 常驻筛选 + 弹性任务主区 + 252px 推荐/安全辅助栏。

- 左栏：全部/线下/线上；日结/周结/月结/完工结；白班/晚班/周末；1/3/5/10km；最低/最高报酬和小时/次/单计价单位。
- 中间：品牌引导、搜兼职/技能/公司/地点、当前城市与真实结果总数、排序、任务流。标题与工价并排，时间/地点、商家、余位、标签、认证与收藏分层展示。
- 右栏：最多 3 个推荐；有技能时用规则匹配，否则展示新近任务。安全提示；登录后展示收藏数与进行中任务入口。未捏造偏好、评分或匹配概率。

任务卡 hover 只有轻微边框、阴影、位移，并尊重减少动画设置。

## 5. 哪些业务组件两端共用

同一 `state`、`app.js` 路由、Supabase client、Auth 登录、11 个服务：auth、task、application、favorite、message、inbox、notification、review、merchant、location、recommendation。

共用任务卡数据、筛选状态、搜索/排序/分页、报名与确认状态机、收藏合并、消息发送与已读 RPC、通知、评价、资料编辑、认证申请、发布与审核。桌面个人中心复用 workerOrders、merchantOrders、publishedList；桌面会话侧栏复用 renderInboxRows。

联系商家遵守原规则：商家确认报名后开放聊天。没有为桌面端绕过这项业务约束。

## 7. 哪些数据仍使用 LocalStorage

- **没有配置 Supabase 时**：保留本地演示模式，用户、任务、报名、消息、收藏、评价、通知、认证模拟等全部仍存在 `huoda_mvp_v050`。这只是演示，不提供真实跨设备同步；页面已明确显示。
- 游客临时收藏：`huoda_favorites_v050_guest`；登录后合并到账号收藏，成功才清除游客记录。
- Supabase SDK 默认保存登录会话凭据，用于重新打开后保持登录。这是 Auth 会话存储，不是业务数据副本；没有自行保存密码。
- 当前筛选、位置与表单/聊天草稿主要在页面内存中；刷新网页会丢失未提交草稿，不承诺草稿跨设备。

所以不能把“代码已经有云端分支”解释成“当前本地演示数据已经上云”。

## 8. 是否修改数据库

新增第 4 份增量迁移，**没有创建 PC 专用业务表，也没有增加重复的用户/任务/消息表**：

1. search_tasks_v051：在现有服务器查询上增加报酬最小值、最大值、计价单位。先过滤再算总数和分页；金额仍用整数分。没有薪资条件时兼容原 RPC。
2. sync_merchant_task_badges + trigger：受保护商家认证记录变化时，更新 tasks.verified 显示缓存；迁移时也校正旧标识。任务审核状态仍独立由审核机制管理。

这份 SQL 已在隔离 PGlite 测试执行，**没有在真实 Supabase 执行**。旧库只追加未执行的迁移，不能重跑旧基线覆盖权限。

## 9. 是否修改 RLS

没有放宽或重写既有 RLS。继续本人资料/收藏/通知隔离、报名参与方隔离、任务 owner 权限、审核员隔离。新搜索 RPC 与原公开任务可见条件一致；新 trigger 函数撤销普通用户执行权。

真实 SQL 测试验证普通用户不能直接改认证、审核、名额、已读时间或后台权限；不能替第三人报名/评价/读私聊。管理员 RPC 继续仅允许 service_role 后端调用，并验证 admin_users。

## 10. 是否使用 Supabase Realtime

继续复用 messages 和本人 notifications 的 Realtime 订阅。事件只触发重新读取云端数据；另外每 15 秒在可见页面重读，切回窗口也重读，覆盖断线及未发布到 Realtime 的表。保留聊天输入、光标、历史滚动位置；不刷新覆盖未提交发布表单。

八项跨会话测试关闭了 Realtime，验证的是同数据源重读和断线兜底。真实 WebSocket 推送、部署权限和真实手机网络体验仍待云端验收。[Supabase 对重读与 Realtime 的说明](https://supabase.com/docs/guides/troubleshooting/realtime-postgres-changes-troubleshooting)。

## 11. 实际测试了哪些分辨率

375×812、430×932、768×1024、1366×768、1440×900、1920×1080。

每种尺寸运行首页、搜索、排序、任务详情、发布表单、消息入口、游客个人中心，并补测已登录个人中心及实际聊天。页面 scrollWidth 不大于视口宽度。检查了手机底部导航、电脑顶部导航、三栏/两栏切换、sticky 详情操作、PC 常驻筛选、聊天草稿刷新保护。

最终执行 `npm run check`：35 个 JS 文件语法检查通过。`npm test`：23 项通过、0 失败；包含 8 个顶层场景、15 个数据库子场景。浏览器为本机 Chromium，数据库为 PGlite 0.3.14。截图与尺寸记录在 `test-results/responsive/`。

## 13. 已知问题与尚未完成项

1. **当前没有真实 Supabase 项目配置与公网站点，完整最终验收未完成。** 需准备同一个项目、部署迁移/审核函数、配置 Auth，再用真实手机和电脑补跑八项。
2. 本机启动服务监听 127.0.0.1，适合本机预览。手机不能直接使用电脑的 localhost；真实跨设备需部署一个双方可访问的 HTTPS 地址。
3. 真实 Auth 邮件、PostGIS 距离/索引、Storage 上传/签名地址、Edge Function 403 和跨连接抢最后名额未执行。原 TESTING.md 保留具体步骤。
4. 未采集工作偏好，推荐目前只有技能、位置、新近程度；没有“最近浏览”持久化。
5. 沿用现有边界：单会话最近 200 条、通知最近 100 条，无历史翻页；报名/发布列表受 API 行数上限影响。offset 分页在数据持续变化时可能漂移。
6. 头像采用 HTTPS URL，尚无单独头像上传器。完成操作仍允许任一参与方提交，未加入资金结算或争议仲裁。
7. 本地演示账户及认证审核模拟不具备线上安全边界；不能保存真实业务。LocalStorage 历史演示不会自动成为真实 Auth 账号。

下一步见《云端接入_从这里开始.md》。项目所有者只需先创建/打开 Supabase 项目；公开地址与 publishable key 足以配置前端，数据库迁移和审核函数部署还需要项目拥有者的控制台或 CLI 授权。
