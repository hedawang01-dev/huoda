# 让手机和电脑共用数据：从这里开始

现在界面和接入代码已经做好，但还缺一个实际的“网上数据库”和一个手机能访问的网址。可以先双击项目里的《启动活搭.cmd》体验电脑端；此时是本地演示。

你不用先学数据库。第一步只要创建或打开一个属于自己的 Supabase 项目。

## 第一步：打开项目控制台

打开 [Supabase 控制台](https://supabase.com/dashboard)，登录或注册自己的账户。已有项目就使用现有项目；没有则创建一个用于活搭测试的项目。手机、电脑共用这一个项目。

数据库密码由你自己保存，不要填进前端 config.js，也不要发到公开文档。

## 第二步：找到两项公开连接信息

在项目的 Connect 面板找 Project URL 和 publishable key；API Keys 也可在 Settings → API Keys 找到。复制两项：

- Project URL：类似 `https://你的项目编号.supabase.co`。
- Publishable key：通常以 `sb_publishable_` 开头；旧项目也可使用 anon key。

这两项用于连接浏览器。**不要使用 secret 或 service_role key，它们只属于后端。** [官方密钥说明](https://supabase.com/docs/guides/getting-started/api-keys)。

找到后可以告诉 Codex“我已打开 Supabase 项目”，继续完成配置与部署；不必自己改 SQL。仅有这两个公开参数还不能代替数据库初始化。

## 第三步：由开发者初始化数据库

如果是全新空项目，按这个顺序在 SQL Editor 执行：

1. `supabase.sql`
2. `supabase/migrations/202609100001_v050_foundation.sql`
3. `supabase/migrations/202609100002_task_edit.sql`
4. `supabase/migrations/202609100003_message_inbox.sql`
5. `supabase/migrations/202609100004_desktop_sync.sql`
6. `supabase/migrations/202609110005_service_hardening.sql`

如果是已经在用的活搭数据库，先核对执行记录与备份，只补尚未执行的文件。**不要重跑旧基线。** 详细事项在 MIGRATION.md。

然后将第二步的信息填入项目 `config.js` 的 `SUPABASE_URL`、`SUPABASE_KEY`。其它页面和手机端会共用它们，不增加第二套配置。

## 第四步：准备测试账号和审核入口

在自己的测试项目建立求职者、商家、管理员三类测试账号，密码由你设置。管理员权限只能通过数据库管理员加入 admin_users；商家不能自行批准任务。

开发者部署 `supabase/functions/admin-review`，并配置允许的后台网址。只有后端使用服务角色密钥，前端公开文件不能包含它。

`supabase/seed.sql` 用于隔离测试项目，不能直接向生产库填充假岗位。也可以注册真实测试账号后走商家认证、发布和审核流程。

## 第五步：提供同一个 HTTPS 网址

本机的 `http://127.0.0.1:8085` 只能在这台电脑上预览。需要将同一个 Web 项目部署为手机和电脑都能访问的 HTTPS 站点，再配置 Authentication → URL Configuration 中的 Site URL 与允许的回调 URL。[官方回调地址说明](https://supabase.com/docs/guides/auth/redirect-urls)。

手机和电脑打开同一个网址，用同一个账号登录。请不要分别开两个数据库。

## 第六步：真正验收

手机收藏，电脑查看；手机报名，电脑商家确认；电脑发消息，手机回复；发布审核后两端可见；修改资料、评价和认证后两端一致。完整八项验收在《V051_PC_开发验收报告.md》及 TESTING.md。

只有在真实项目、真实登录、真实手机/电脑都通过后，才能把“已真实互通”这一项标为完成。当前交付包含代码和本地测试证据，没有替你创建账号、购买服务或发布公网网站。
