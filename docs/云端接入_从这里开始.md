# 活搭 5.4 云端接入：从这里开始

当前已有关联 GitHub 私有仓库，94754e1 还保留 2026-09-12 的 Supabase 部署历史记录；本次没有重验云端或发布 Vercel。下面的创建步骤仅用于另建隔离项目或重建，不要在现有数据库重复初始化。数据库密码、高权限 key 和管理员密码都由你自己保管，不要发给 Codex，也不要写进前端。

## 1. 创建 GitHub 空仓库

1. 登录 https://github.com/，点击 New repository。
2. 仓库名可用 huoda，公开或私有均可。
3. 不勾选自动生成 README、.gitignore 或 License。
4. 创建后保留仓库 HTTPS 地址。

在项目目录执行：

    git remote add origin https://github.com/YOUR_NAME/huoda.git
    git branch -M main
    git push -u origin main --tags

## 2. 创建 Supabase 项目

1. 登录 https://supabase.com/dashboard，选择 New project。
2. 项目名可用 huoda，区域选择靠近主要用户的位置。
3. 设置数据库密码并保存到自己的密码管理器。它不进入前端。
4. 项目就绪后，优先使用项目内 Supabase CLI 按 MIGRATION.md 顺序 dry-run 并部署基础迁移和 001–006；不要再在 SQL Editor 重复执行根目录 `supabase.sql`。
5. 不要在生产项目运行 supabase/seed.sql。

在 Connect 或 Settings → API Keys 找到：

- Project URL：https://项目编号.supabase.co
- Publishable key：通常以 sb_publishable_ 开头

这两项是浏览器公开连接值。不要选择高权限 key。

## 3. 配置 Supabase 功能

1. 在 Authentication → URL Configuration 暂时加入 http://127.0.0.1:8085。
2. 注册测试管理员账号后，只在 SQL Editor 把它加入 admin_users。
3. 安装 Supabase CLI 后部署 supabase/functions/admin-review。
4. Vercel 域名确定后，把它设置为 Auth Site URL/Redirect URL，并写入 Edge Function 的 ADMIN_ALLOWED_ORIGINS。

## 4. 创建 Vercel 项目

1. 登录 https://vercel.com/dashboard，选择 Add New → Project。
2. 导入 GitHub 的 huoda 仓库。
3. Framework Preset 选择 Other。构建命令和输出目录会从 vercel.json 读取。
4. 添加环境变量 HUODA_SUPABASE_URL 和 HUODA_SUPABASE_PUBLISHABLE_KEY。
5. 点击 Deploy。

生产构建缺少任一公开配置会主动失败，不会发布成本地演示网站。

## 5. 把三者连起来

Vercel 发布后会得到 https://....vercel.app：

1. 将该域名加入 Supabase Authentication 的 Site URL 和 Redirect URLs。
2. 在 Supabase Edge Function 环境把 ADMIN_ALLOWED_ORIGINS 设置为这个 HTTPS Origin，然后重新部署函数。
3. 用该域名访问 / 和 /admin/。
4. 手机和电脑打开同一个网址，并使用同一个 Supabase 账号。

## 6. 真实验收

- 手机收藏，电脑能看到；电脑取消，手机刷新后消失。
- 用户报名后，商家依次标记已查看、发起沟通、录用/不录用。
- 沟通中和已录用可双向聊天；完成后聊天只读。
- 商家保存草稿、提交审核；管理员审核后公开；招满、结束、下架状态正确。
- 完成后双方评价；用户举报；管理员处理后通知同步。
- 营业执照不公开，普通用户和非管理员不能访问。
- 刷新详情、聊天和后台路径正常，六档手机/平板/PC 布局无横向溢出。

只有真实项目、真实 HTTPS、真实手机和电脑全部通过，才可以标记“公网与跨设备已验收”。

## 7. 以后自动发布

Vercel 与 GitHub 连接后，日常修改只需：

    git add -A
    git commit -m "说明本次修改"
    git push

GitHub Actions 先做质量检查；Vercel 对分支生成预览，对 main 自动发布正式版本。
